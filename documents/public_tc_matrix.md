## 우선순위와 측정

공통 인증·대화 상태·중복 접수 보호를 먼저 점검하고, 실제 어댑터가 준비된 L-23·L-11부터 API 실행 흐름을 연결한다. L-20과 Y-24는 API 없이도 정책 응답을 검증할 수 있다. 가격·상품·배송·환불 문의의 경계는 나머지 사례에도 재사용한다. 평가 배점은 비공개이므로 특정 사례의 배점을 추정하지 않는다.

각 검증은 공개 TC의 여러 대화 단계, 실제 호출 대상·요청 본문·접수 결과, 금지된 호출 여부, 500자·10건 제한, 실제 응답 시간·말풍선 수·길이를 별도로 기록한다. 국소 모의 단위 시험은 진짜 API나 카카오 왕복 성공이 아니다. 모델은 고객 발화와 조회 결과에 없는 사실을 만들어내지 않고, 접수 성공 전 완료를 주장하지 않는다.

카카오 게이트웨이 공식 `MESSAGE_CREATE` 표에는 문자열 `content`와 채팅방/발화자 키가 표시되지만 이미지·음성 전달 필드는 기재돼 있지 않다. 실제 이미지·음성 이벤트의 표현과 처리 경로를 확인하기 전에는 이 두 TC를 지원한다고 주장하지 않는다.

2026-10-31 14:06 기준: API 어댑터는 24·28·32·33도 추가했으나 접수 라우터에는 연결되지 않았다. [L-11/L-23 주문 흐름](../order_workflow.py)은 가짜 API와 명시적으로 검증된 인증 컨텍스트에서 시험했다. 실제 평가의 인증 정보는 어디서 오는지 미확인이며 게이트웨이에 임의 추정해서 연결하지 않았다. 공개 TC의 주문번호·고객정보를 다른 사례에 사용하지 않는다.

사용자가 `practice_readonly.zsh`를 실행하고 액션 키를 직접 입력했다. 공개 TC `L-60`, 할인 코드 `SUBAK15`에 대해 실제 서버 조회 결과 `succeeded`, HTTP 200과 15%·유효기간·수박 대상·중복 조건이 담긴 응답을 사용자 터미널에서 확인했다. 상품 할인 조회 1건이며 실제 카카오톡이나 전체 L-60 상담은 아니다. 터미널에 표시된 총 시간에는 키 입력 대기 등이 포함되어 응답 지연·p95로 취급하지 않는다.
