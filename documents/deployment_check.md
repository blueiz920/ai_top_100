# 제출 대상과 로컬 운영 상태

2026-10-31 14:00경 카카오디벨로퍼스 앱 목록을 읽어 이 계정에 앱 1개가 있고 **App ID `1630436`**, 해당 앱 안에 `ai_top_100` 봇이 생성되어 있음을 확인했다. 봇 인증 토큰은 읽거나 이 문서에 기록하지 않았다. App ID를 제출란에 입력하거나 제출한 것은 아니다.

대회 가이드는 직접 서버 또는 **로컬 게이트웨이**를 모두 허용한다. 제출할 App ID에 연결된 봇이 완성된 에이전트에 연결되어 있고 운영진 평가 계정이 접근할 수 있으며 최종 버전이 실제 실행되어야 한다. 사용자가 검색 허용 끄기·채널 공개 유지·채팅 끄기를 완료했다고 보고했으나, 운영진 계정 접근 가능 여부까지 독립 확인한 것은 아니다.

13:51경 프로세스 목록 확인에서 에코봇과 Ollama 서버는 발견됐고 `gateway_ai_bot.py` 프로세스는 발견되지 않았다. 14:17 사용자가 에코봇을 종료한 뒤 Ollama만 남고 로컬 서버 버전 API가 응답하는 것을 확인했다. **14:19 AI 봇 `READY`와 공개 L-60의 실제 카카오→할인 조회→카카오 답장을 확인했다.** 사용자 터미널 로그는 응답 0.739초·145자·1말풍선이다. AI 봇 코드에는 상품·프로모션 조회와 제한된 안전·신원확인 이관이 연결되어 있다. 주문 소유권 확인·환불은 실제 통합 전이다. 공개 TC 전체와 실제 접수는 미검증이다.

## 실행 준비

- `start_ai_bot.zsh`는 카카오 봇 토큰과 대회 액션 API 토큰을 필요하면 터미널에서 입력받는다. 입력은 화면에 표시하지 않으며 토큰을 파일이나 커밋에 저장하지 않는다. Ollama가 이미 켜져 있어야 한다.
- AI 스크립트의 `READY`와 L-60 한 건의 카카오 왕복을 사용자 로그·대화창으로 확인했다. 에코봇은 사용자 확인 후 종료했다. 같은 봇의 중복 게이트웨이 연결은 한 연결을 대체할 수 있다.
- 스크립트는 실행 중 `caffeinate -i`로 유휴 잠자기를 방지한다. 이는 덮개를 닫아도 가동된다는 보장이 아니다. 전원을 연결하고 덮개를 열어 두며 네트워크와 두 프로세스를 유지해야 한다. 재부팅 후 자동 기동은 설정하지 않았다.
- 14:12경 전원 상태 조회 결과 AC 전원에 연결되어 충전 중이었다. 이는 그 시점의 확인이며 심사 종료까지 전원이 유지된다는 보장은 아니다.
- 14:19 확인한 Ollama 서버는 Codex CLI 자식이었고, 14:20경 독립 백그라운드로 전환한 직후 부모 PID 1·모델 목록·로컬 추론(4.99초)을 확인했다. 그러나 14:21 실제 카카오 귤 보관 질문이 일반 재질문으로 돌아왔고 해당 서버는 종료된 상태였다. 종료 원인은 미확인이다. **14:23 사용자가 별도 VS Code 터미널에서 서버를 기동했고 14:24 카카오 봇이 동일 질문에 올바른 보관법을 답했다.** 두 터미널 모두 유지해야 하며, 재부팅 후 자동 기동은 설정하지 않았다. 덮개·전원·네트워크 관리가 필요하다.
- 14:17경 최종 봇이 사용할 영속 액션 저널 파일은 아직 존재하지 않았다. 이후 연습 접수 결과가 불명이면 임의 삭제·재접수하지 않는다. 연습 결과 불명이 평가 시작 이후 조회까지 막는 결함은 모의 회귀에서 수정 확인했으며, 이전 연습 쓰기 결과가 불명이면 평가 중 새 쓰기는 여전히 차단된다.
- 실제 봇으로 카카오 응답, 액션 API의 기대된 조회/접수, 실패 시 응답, 평가 계정 접근을 검증하고, 제출 이후에는 11월 1일 24:00까지 상태를 바꾸지 않는 대회 규정을 지킨다. 제출과 변경성 연습 호출·데이터 리셋은 각각 별도 사용자 승인을 받는다.

## 14:50 전 실제 연결 검증 후보 — 미실행
