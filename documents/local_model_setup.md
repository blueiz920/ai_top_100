# 로컬 응답 모델 준비 현황

2026-10-31 사용자 요청으로 공식 Ollama macOS 배포본을 내려받아 앱의 macOS 서명을 검증하고 `.local-ai/Ollama.app`에 보관했다. Qwen3 `qwen3:4b-instruct-2507-q4_K_M` 모델 약 2.5GB의 다운로드와 Ollama SHA-256 검증이 완료됐다. 앱·모델은 `.local-ai/`에 저장하며 Git 추적에서 제외한다. 사용자 토큰은 저장하거나 사용하지 않았다.

로컬 서버는 `127.0.0.1:11434`에서 동작하고, `OLLAMA_NO_CLOUD=1`로 클라우드 추론을 끈다. 모델 다운로드에는 인터넷이 필요했고, 시험 질문의 추론은 이 맥에서 수행했다. 서버를 다시 시작할 때만 프로젝트 디렉터리에서 다음을 실행한다.

```sh
zsh start_local_ai.zsh
```

이미 서버가 동작 중이라면 같은 명령을 중복 실행하지 않는다. 터미널에서 명령이 동작하는 동안 서버가 유지되며, 재시작·잠자기·네트워크·전원 등에 대비한 심사 기간 운영 방법은 별도 검증이 필요하다. 이 설치는 자동 실행 설정이 아니다.

14:20경 Codex CLI 자식으로 실행 중이던 서버를 독립 백그라운드로 전환해 부모 PID `1`, 동일 모델 목록, 감귤 보관 질문 추론(4.99초)을 확인했다. 그러나 14:21 실제 카카오 질문 때 서버가 종료되어 포트 연결이 거부됐다. 종료 이유는 미확인이다. **14:23 사용자가 VS Code의 별도 터미널에서 서버를 실행했고, 14:24 동일 카카오 질문에 올바른 보관법이 한 말풍선으로 돌아온 것을 확인했다.** 운영체제 재부팅 후 자동 실행은 설정하지 않았다. 이전 서버 로그는 Git에서 제외한 `.local-ai/ollama-service.log`에 있다.

14:24 서버 `/api/ps` 확인상 사용 중인 모델은 약 3.18GB이며 기본 유휴 보관 시간은 5분이다. 메모리 여유는 그 시점 약 26%였다. [Ollama 공식 FAQ](https://docs.ollama.com/faq)는 `keep_alive`로 메모리 보관 시간을 조절할 수 있다고 설명한다. 사용자가 모델 상시 유지를 선택하여 14:25 빈 로컬 요청에 `keep_alive: -1`을 적용했고 `/api/ps`에서 장기 유지 상태를 확인했다. 기존 봇처럼 `keep_alive`를 생략한 단발 로컬 호출 뒤에도 유지 상태가 계속된 것을 확인했다. 이후 추론마다 설정을 명시하도록 `local_model.py`에도 반영하고 모의 시험했다. **이미 기동된 AI 봇은 이전 코드를 사용하므로 수정 코드 자체는 다음 재시작부터 적용된다.** 메모리 여유와 실제 p95 개선은 계속 확인해야 한다.

## 초기 기능 시험

가상 규칙과 가상 주문번호를 이용한 단발 시험이다. **실제 고객 데이터·대회 액션 API를 사용하지 않았다.**

- 간단한 한국어 파손 상담: 최초 응답 6.10초(모델 로딩 4.12초 포함). 가상 규칙에 따라 주문번호와 사진을 요청하고 환불 완료를 약속하지 않았다.
- 가상 `lookup_order` 도구 호출: 1.48초. 모델이 `TEST-123`을 매개변수로 포함한 도구 호출을 생성했다. 이는 모델이 요청을 생성한 것만 확인한 것이며, 실제 액션 API를 호출하거나 주문을 조회한 결과가 아니다.
- 가상 다회 대화의 환불·건강 문의: 3.98초. 산식에 제시된 4,000원은 맞혔지만, 근거에 없는 '건강 상담팀'을 만들어내고 도구 실행 없이 처리·이관을 예고했다. 따라서 그럴듯한 답변을 실제 접수·이행으로 취급할 수 없다. 정책 및 API 실행 결과를 별도로 검증하고 존재하지 않는 담당자를 만들지 않도록 해야 한다.
- 각 1회 시험이므로 p95·실제 케이스 정확도·긴 문맥 응답 성능은 미측정이다. 실서비스 적용 전에 공개 테스트와 실제 카카오 왕복 검증이 필요하다.

## 현재 결합 상태

기존 `gateway_echo_bot.py`는 메시지를 그대로 되돌려주는 에코봇이다. 별도 `gateway_ai_bot.py`에 로컬 모델, 지식 선택과 상품·프로모션 읽기 라우터를 연결했다. 14:06 사용자 터미널에서 동일 읽기 라우터로 공개 L-60 프로모션 실제 조회 HTTP 200을 확인했지만, AI 봇은 실제 카카오 게이트웨이로 시작하거나 카카오 왕복을 검증하지 않았다. 주문·환불·이관은 실제 게이트웨이에서 동작하지 않는다. 기존 실행 중인 에코봇은 재시작 전까지 그대로다.

## 13:16~13:20 근거 선택 모의시험

정책 카드에서 모델이 문장을 직접 지어내지 않고 근거 번호를 고르는 초기 구현을 로컬에서 시험했다. 가예약 질문 5.72초(모델 로딩 포함), 갈치·옥돔 제철 2.28초로 적절한 자료를 선택했다. 곰팡이 섭취 후 복통은 즉시 보관 안내를 반환했다. 배송완료 미수령 질문은 1.41초에 관련 정책을 선택했다. 두 통 중 한 통 하자 및 타인 주문 질문은 처음에 필요한 카드를 찾지 못했다. 이후 같은 박스에 한해 조건부 비율 안내와 타인 정보 거절을 추가하고 경계값을 모의 검증했으며, 실제 환불 처리를 뜻하지 않는다. 각각 단발 측정이므로 p95나 실제 API·카카오 응답속도가 아니다.

## 14:10 공개 사례 중심 모의시험

로컬 모델로 감귤 신맛·미수령·망고 결항·우천 체험·식품 섭취 후 증상 질문을 각 1회 확인했다. 기존 선택 응답은 각각 4.41초·1.15초·2.07초·1.66초·0.00초였으나, 첫 세 경우 주문번호를 묻지 않거나 관련 없는 날짜·정책을 함께 내보냈다. 이후 이 문의의 초기 안내를 근거 기반으로 보완하고 모의 단위 시험을 통과했다. 한 번씩 측정한 로컬 시간은 p95나 실제 카카오 왕복 시간이 아니며, 주문 조회·접수 성공을 뜻하지 않는다.
# 14:40 실제 모델 재확인

서버의 `api/ps`에서 Qwen3 4B가 메모리에 유지되는 것을 확인했다. 실제 로컬 모델+지식 카드 단독 문의 결과: 귤 보관 3.39초·53자, 애플망고 보관 1.55초·76자, 멜론 보관 1.10초·63자. 멜론 답변에는 보관과 직접 관계없는 그물 무늬 설명이 함께 선택됐다. 이는 모델과 지식 선택의 **3건 단독 측정**으로, 카카오 왕복이나 p95 성능을 증명하지 않는다.
