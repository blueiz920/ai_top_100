# 액션 API 공통 규약 — 2026-10-31 읽은 내용

출처: 사용자가 사이드 브라우저에 열어 둔 https://aitop100.org/contest/docs#description/introduction . 이 작업에서는 API 호출, 토큰 입력, 데이터 초기화는 하지 않았다.

- `Authorization: Bearer <액션 토큰>`과 `X-Aitop100-Test-Case-Id`가 필요하다. 평가 전에는 공개 TC ID를 사용하며, 같은 TC를 처리하는 동안 같은 ID를 유지한다.
- 접수 API는 요청을 기록할 뿐 정책 타당성이나 실제 주문·결제 상태 변경을 보장하지 않는다. 정책 판단 후 접수하고 고객에게 접수와 완료를 구분한다.
- **같은 접수 API·같은 대상에 재접수하면 본문이 달라도 기존 접수번호를 반환하면서 내용이 마지막 본문으로 바뀐다.** 단순 중복 호출이라고 내용이 보존된다고 가정하지 않는다. 대상 없는 이관은 같은 본문 기준으로 같은 번호를 반환한다. 요청 전·재시도 전 결과와 본문의 일치 여부를 확인할 설계가 필요하다.
- 60초당 100호출, 평가 중 총 3,000호출 한도. 시간창 429는 Retry-After를 따른다. 평가 누적 429는 기다려도 해소되지 않는다. 같은 조회 반복, 본문 없는 400/404도 호출량에 포함된다.
- 문서상 단건 조회 부재는 본문 없는 404, 검색 부재는 빈 배열. 문서에 없는 경로·메서드도 본문 없는 404이므로 경로를 먼저 확인한다. TC 헤더 오류는 코드가 있는 400, 다른 400은 본문이 없을 수 있다.
- 연습 데이터는 TC 간 공유된다. 제출 후 또는 평가 시작 시각부터는 초기화 불가. 평가 첫 호출 전에 자동 초기화된다. 데이터를 바꾸는 시험은 사용자 승인·검증 계획이 필요하며, 초기화를 이미 수행했다고 가정하지 않는다.

개별 경로, 요청/응답 필드, 오류 처리 및 실제 연동 성공 여부는 추가 확인이 필요하다. 이 공통 규약만으로 평가 준비 완료라고 판단하지 않는다.

## 14:06 공개 TC 실조회

사용자가 터미널에서 자신의 액션 키를 직접 입력해 `L-60` 헤더로 `SUBAK15` 프로모션 조회를 수행했다. HTTP 200과 15%·기간·대상 및 중복 조건 안내를 확인했다. 이는 인증된 액션 API의 읽기 1건 확인이며 실제 평가에서 TC ID가 대화에 어떻게 전달되는지, 카카오톡 왕복과 주문·환불 처리가 되는지는 확인하지 못한다. 총 터미널 소요에는 사용자 입력 대기가 포함되므로 API 속도로 사용하지 않는다.
